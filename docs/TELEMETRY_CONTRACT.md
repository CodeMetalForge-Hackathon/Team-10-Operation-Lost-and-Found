# Telemetry contract

This file is the host-side contract for lines that already exist. It does not change `firmware/node/node.ino` or the over-the-air structs in `firmware/node/protocol.h`.

`docs/ARCHITECTURE.md` section 2 is still the team agreement for the packed radio packets and the five example JSON lines. Where a committed recording disagrees with that example, the recording wins for the host parser. The simulator keeps emitting the architecture examples.

Checked against the JSONL files in `data/` on 2026-11-08. Those files are the physical evidence. This session did not open a serial port.

## Clocks

| Field | Who writes it | Unit | Use |
|---|---|---|---|
| `t_ms` on `feat`, `event`, `device_seen` | Origin node | milliseconds since that node's boot | Evidence time. Not Unix time. Not synchronized across nodes. |
| `uptime_s` on `beacon` | Origin node | seconds since that node's boot, uint16, caps at 65535 | Keep it. It is a real measurement in current firmware. |
| `t_ms` on `gw` | Gateway | milliseconds since gateway boot (`millis()`) | Gateway diagnostic. Not a sensor time. |
| `t_host` in a `data/*.jsonl` file | `tools/record_gateway.py` | Unix seconds, float, millisecond precision | Original capture time. The host copies it to `t_recorded_s` and does not use it for freshness. |
| `t_host` after ingest | This host | Unix milliseconds, integer. Also copied to `t_ingest_ms`. | Freshness. A node is inactive when `now - last_t_host > stale_after_ms` (default 6000). An acoustic cue is fresh for 30 seconds, then `stale`. |

A recorded beacon from `data/beacons_line_2nodes.jsonl`:

```json
{"type": "beacon", "src": 2, "seq": 91, "hops": 0, "rssi_last": -36, "batt_mv": 0, "uptime_s": 186, "floor_db": 0, "nbrs": [[1, -43]], "t_host": 1794088158.947}
```

After ingest at host time `1700000000000`, the observation keeps `uptime_s`, `hops`, and the raw zeros, sets `t_recorded_s` to `1794088158.947`, and sets `t_host` to `1700000000000`.

## Provenance

`/state` and `/ws` carry `source`:

| source | How the process was started | Badge |
|---|---|---|
| `live` | `--gateway`, `GATEWAY_PORT`, and/or `--tcp` | LIVE |
| `recording` | `--recording FILE` | RECORDING |
| `simulation` | `--demo` or `--simulate` | SIMULATION |

`simulated` is true only for `simulation`. A recording is not live hardware. USB and TCP are the same live pipeline; neither has been verified on the Pi.

## Message types

### `beacon`

Observed. Required: `type`, `src` 0–255, `seq` 0–65535, `hops` 0–255, `rssi_last` -128–127, `batt_mv` 0–65535, `floor_db` -128–127, `nbrs` as `[id, rssi]` pairs.

Optional: `uptime_s` 0–65535. Current firmware always sends it. The architecture example omits it; that example still parses.

`nbrs` may include id 0. That is the gateway heard as a neighbor. It does not create a sensor node 0.

### `device_seen`

Observed. Required radio fields plus `t_ms` and `devs`. Each device is `[hash, kind, rssi, count]`. Hash is 8 hex characters. Kind is `BLE_OTHER`, `BLE_APPLE`, `BLE_FINDMY`, `BLE_GOOGLE`, or `WIFI_PROBE`. At most 20 devices. The host does not reverse the hash.

### `feat`

Documented and printable. Not generated by current node firmware. Not in the recordings. If a line arrives, required radio fields plus `t_ms` and `rms_db`, `low_db`, `voice_db`, `high_db`, `peak_db`, each -128–127. Do not treat a parsed example as a hardware detection.

### `event`

Same status as `feat`. Required radio fields plus `t_ms`, `kind`, `peak_db`, `voice_db`, `count`, `conf`.

Kinds the host accepts as known: `LOUD`, `TAP_PATTERN`, `VOICE_LIKE`, `RADAR_PRESENCE`, `GAS`, `VIBRATION`, `MOVED`.

A structurally valid kind outside that list, including the old gateway's `UNKNOWN`, is accepted. The original kind and payload are kept. `kind_status` is `unclassified`. It does not raise search priority. A non-token kind is still rejected.

`VIBRATION` is an SW-420 burst. It is a known kind and can raise a fresh acoustic cue. It is not an accelerometer reading.

`LOUD`, `TAP_PATTERN`, `VOICE_LIKE`, and `VIBRATION` can raise a fresh acoustic cue. The cue expires after 30 seconds. `MOVED` does not raise one. `RADAR_PRESENCE` and `GAS` are named and not fitted.

### `range`

Printer exists. No recording. The architecture example omits `seq`, `hops`, and `rssi_last`. The firmware printer includes them because it uses the same radio prefix as the other types. The host requires `src`, `chirper`, `delay_us`, `snr_db`. If `hops` is present it is kept. `delay_us` is not converted to metres.

### `gw`

Observed diagnostic. Required: `id`, `t_ms`, `rx_dropped`. No `src`. It updates `gateway` in `/state` and does not create a node.

```json
{"type": "gw", "id": 0, "t_ms": 306574, "rx_dropped": 0, "t_host": 1794088158.746}
```

### `log`

Recorder type, or a non-JSON serial line wrapped by the recorder. Required: non-empty `text`. Stored under `diagnostics.logs`. A `# sent CMD ...` line is a firmware text echo, not an observation.

### `host_cmd`

Recorder type only. Required: non-empty `text`, such as `CMD BLINK 0 255`. Stored under `diagnostics.host_cmds`. The host does not send this back to a board.

Over-the-air `CHIRP` and `CMD` packets are not printed as JSON. The gateway accepts text commands on USB: `CMD HAIL 0 255`. This host still does not send them.

## Firmware after `153bab1` (not a new capture file)

William's node sketch now generates `feat` and `event` on `ROLE_NODE`. The JSON object shape did not change. No new JSONL file was added. His written N2 bench note is in `docs/DECISIONS.md`. This host has not replayed a capture of those events.

| Field | Current firmware | Host reading |
|---|---|---|
| `batt_mv` | Still hardcoded 0. | Raw 0, status `unimplemented`. |
| `floor_db` | `lround(audioFloorDb)`. Starts at 0 until the audio task runs. Gateway stays 0. After warm-up it is dBFS re 2048 counts, usually negative. | 0 stays `unimplemented`. Any other value is `reported`. A true 0 dBFS floor would be mislabeled; current firmware uses 0 only before warm-up and on the gateway. |
| FEAT `low_db`, `voice_db`, `high_db` | Always `-128` on the Grove sensor. | Raw `-128`, status `unavailable`. Not a measurement. |
| FEAT `rms_db`, `peak_db` | Computed dBFS, clamped to -127..0. | `reported` unless the value is `-128`. |
| EVENT `voice_db` | `-128` except `VOICE_LIKE`, where it is the average level, not a voice-band energy. | `-128` is `unavailable`. A non-sentinel value is `reported`. |
| `VIBRATION` | SW-420 burst. `count` is edge count. Not the parked accelerometer. | Accepted. Raises search priority as a contact cue. Not a location. |
| `MOVED` | Still reserved. Nothing sends it. | Accepted if it arrives. Does not raise search priority. |
| `VOICE_LIKE` | Any sustained sound, not a voice classifier. | Same event kind. The page label is "Sustained sound". |

ESP-NOW is still channel 1. The new sketch does not call `WiFi.begin()` and does not open TCP. USB JSON printing is unchanged. The mesh still de-duplicates by `(src, seq)` before a forward. This host does not drop a repeated line; the database keeps both deliveries so two events are not collapsed.

Old `data/*.jsonl` files still parse. Their `floor_db` 0 remains unimplemented.

`sendBeacon()` still sets `batt_mv = 0`. `floor_db` is 0 only until the audio task has a floor, and always 0 on the gateway. After warm-up a field node sends a real dBFS floor. The host still treats 0 as unimplemented so the old recordings and the gateway stay honest.

The host keeps the raw integers. In `/state`, `batt_mv_status` and `floor_db_status` are `unimplemented` when the value is 0, `reported` when it is non-zero, and `absent` when the field never arrived. A dB field of `-128` is `unavailable`, which is a different sentinel from 0.

A later firmware that measures a true 0 dB floor must stop using 0 as the sentinel, or the host will mislabel it. 0 mV is not a plausible cell voltage.

`rssi_last` of 0 would be a reported radio value. Current recordings do not contain it. The receive callback uses 0 only if `rx_ctrl` is missing. Do not invent a status flag for that until a recording shows it.

## Validation

A bad JSON line is logged and skipped. The next line is still accepted. A `#` firmware note is stored as a `log` diagnostic, not rejected as JSON. Unknown `type` is logged and skipped. `gw`, `log`, and `host_cmd` are not unknown.

Out-of-range integers and a bad device hash are rejected. They do not clear state. A failed database write is counted and does not stop the next line.

## Heatmap

`fusion/heatmap.py` is William's separate estimator. It reads recorder JSONL, where `t_host` is Unix seconds, or a serial port it owns itself. `as_unix_seconds` converts a host ingest millisecond if one is passed in. Hand-entered positions in `data/live_3node_test1.meta.json` are not a survey. Its page is an experimental search region. The operator dashboard does not show that output, and this host does not send `CMD` lines. Firmware can accept `CMD HAIL`, `CMD PING`, and `CMD BLINK` on the gateway serial port. One process can own that port. Two processes cannot.
